OpenClaw vs Hermes Agent vs OpenHuman — AI Agent 三层生态深度对比

2026-05-29

2026 年如果你关注开源 AI 领域，这三个名字一定绕不开。它们各自成长极快，GitHub 上动辄数万星，社区讨论铺天盖地。

但它们真的是一回事吗？

答案是否定的——它们解决的是完全不同层面的问题。读完之后你不仅知道「哪个更好」，更知道「我的问题属于哪一层」。

一个框架先帮你锚定：三层生态

在深入每个项目之前，先建立这个坐标系，后面所有对比都会落回这张图：

环境层让 AI 跑起来、能操作工具；执行层让 AI 学会更聪明地干活；记忆层让 AI 真正理解你的上下文。这三层互不冲突，甚至可以叠加使用。

一、OpenClaw — 环境层：把 AI 从 App 里解放出来

解决什么问题

你现在跟 AI 对话是在哪个界面？ChatGPT 网页、Claude 客户端、还是某个 IDE 插件？不管哪种，AI 都被「锁」在了那个 App 里。你想在微信上喊它查个东西，它不在。你想它帮你操作浏览器，它做不到。

OpenClaw 的核心方案是一个Gateway（网关）——你可以把它理解成一个消息中转站。你在微信发出的消息，先到 Gateway，Gateway 判断该调用哪个能力（浏览器、代码执行、还是知识库），执行完后原路返回给你。这个设计的关键在于：无论消息来自哪个平台，Gateway 都转成统一格式处理，处理完再转回对应平台的格式发出去。所以你只需要写一套 AI 逻辑，就能在所有平台上用。

它怎么做到的

技术层面看，OpenClaw 是 Rust 编写的守护进程（daemon），常驻在你电脑后台，主要靠三个核心技术运转：

1. CDP（Chrome DevTools Protocol）——做浏览器的遥控器

CDP 是 Chrome 开放的一组 API，外部程序可以通过 WebSocket 连接浏览器，执行打开页面、点击按钮、填写表单、截图等操作。几乎所有浏览器自动化工具（Playwright、Puppeteer）底层都在用 CDP。OpenClaw 在此基础上封装了一层「快照-动作」模式：

  • 先用 browser snapshot 给页面拍快照，生成一棵结构化 UI 树，每个可交互元素获得一个唯一 ref ID
  • AI 分析 UI 树，决定操作目标
  • 用 browser act --ref <ID> 执行点击或输入

为什么不用传统的 CSS 选择器？ 因为网页经常改版，CSS 选择器很容易失效。ref ID 是 OpenClaw 自己生成的，完全不依赖网页 DOM 结构，稳定性高得多。

2. 多 Profile 隔离

OpenClaw 有一个独立的浏览器用户数据目录，跟你的个人 Chrome 配置完全隔离（甚至默认用橙色主题作视觉区分）。它还支持创建多个 Profile（比如一个用于工作、一个用于远程）——每个 Profile 可以有独立的浏览器可执行文件、CDP 端口、代理设置，甚至不同的配色。

3. 插件系统与 Skill（技能）

OpenClaw 的社区生态围绕插件和技能展开。技能包本质上是可复用的操作指南——比如一个「浏览器自动化」技能会告诉 AI 完整的「先快照→分析→再操作」流程。你不需要从头教 AI 每一步。

一句话总结

OpenClaw 是唯一能让你在微信、Telegram、Slack 同时使用同一个 AI 的工具，同时赋予它操控浏览器和执行代码的能力。但它的安装和学习门槛也最高，适合愿意折腾 CLI 的用户。

二、Hermes Agent — 执行层：让 AI 学会做事并记住怎么做

解决什么问题

你用 AI 搭了一套环境、写了一个自动化脚本，效果很好。但第二天来了个类似任务，AI 完全忘了昨天做过什么，重新推理一遍，还可能犯同样的错。你心想：为什么 AI 不能像人一样积累经验？

Hermes Agent 的核心理念就在于此——它不只是执行任务，还会从每次执行中提炼经验，把「怎么做」固化为可复用的能力。

最独特的能力：闭环学习系统

Hermes Agent 的运行逻辑是一个闭环：

Step 1: 接受任务 → AI 思考步骤、调工具、逐项执行
Step 2: 完成任务 → AI 回顾整个执行过程，识别可泛化的模式
Step 3: 提炼技能 → 把操作步骤抽象化，写成 SKILL.md
Step 4: 存入技能库 → 下次遇到类似任务直接调用，无需重新推理

这里的泛化（Generalization） 是关键。Hermes 不是简单地「录制操作日志」，而是理解问题模式。比如「在服务器上部署 Nginx」这个任务，它会提炼为：「检测目标 OS → 根据 OS 执行对应安装命令 → 复制配置文件 → 重启服务」。换个 Linux 发行版照样能用。

学到的技能存在本地技能库，遵循开放的 SKILL.md 格式，兼容 agentskills.io 标准，社区之间可以互通共享。

持久记忆系统

记忆靠两套机制协同工作：

  • FTS5 全文搜索：SQLite 内置的全文索引引擎，可以毫秒级检索历史对话和操作记录
  • LLM 自动总结：每次交互结束后，AI 自己判断哪些信息值得长期保存（用户偏好、项目关键决策、常用配置），消化成结构化摘要存入数据库

下次你打开新会话，Hermes 会自动拉取跟当前上下文相关的记忆片段，注入到提示中。这就是「不会每次从零开始」的实现原理。

并行子 Agent 架构

对于可拆解的大型任务，主 Agent 作为协调者（Orchestrator），通过 RPC（远程过程调用）把子任务分发给多个子 Agent。每个子 Agent 有独立的对话上下文和终端沙箱环境，互不污染：

主 Agent（总指挥）
    ├── 子 Agent 1：搜索资料并整理摘要
    ├── 子 Agent 2：基于摘要编写代码
    └── 子 Agent 3：在独立沙箱中跑测试并汇报结果

这带来了三个好处：任务级并行加速、上下文隔离（一个子任务的 token 不会污染另一个）、以及水平扩展能力（加子 Agent 就能加吞吐量）。

执行安全

Hermes 提供四种可选的执行沙箱： - 本地终端：直接执行（适合开发调试） - Docker：隔离容器，只读根文件系统 + 权限降级（推荐生产使用） - SSH：远程执行，用于管理云服务器 - Modal / Singularity：高性能计算环境

一句话总结

Hermes Agent 是唯一能自动从经验中学习、越用越聪明的 AI Agent。它的「闭环学习 → 自动创建技能」在同类中是独一份，但需要你愿意花时间让它积累，适合研究者和重度开发者。

三、OpenHuman — 记忆层：让 AI 真正记住你的一切

解决什么问题

你跟 AI 聊了半小时自己的项目背景、偏好、近期动向。第二天打开同一个 AI，它问「你是谁……」。更气人的是，你明明有大量的数据分布在 Gmail、Notion、GitHub、日历里，但 AI 完全不知道它们存在，也读不了。

OpenHuman 的答案是：把 AI 做的第一件事从「对话」变成「了解你」。

独特的技术架构

OpenHuman 是这三个项目中唯一拥有原生桌面 GUI 的，基于 Rust + Tauri 框架构建（不是常用的 Electron，性能更好、安装包更小）【这里一些英文需要解释一下】。macOS 上是 DMG 安装包，Windows 上是 EXE，下载双击即装。打开后是一个完整的桌面应用——有聊天面板、有可视化工作区、有连接状态指示。

但 GUI 只是表象，真正核心的是三层技术系统：

第一层：Memory Tree（记忆树）

这是 OpenHuman 区别于所有同类项目的根本。大多数 AI 的记忆系统基于向量数据库 + 相似度搜索——相当于在文件柜里把所有便利贴混在一起，搜的时候靠「语义上大概像」。Memory Tree 不同，它把信息组织成三层树状结构：【openclaw 没有吗，他的记忆系统是什么样的】

全局层（Global）          ← 概括性知识：「用户是产品经理，关注 AI 和社区方向」
    ↑
主题层（Topic）           ← 按项目/主题分类：「小红书面试准备」、「硕士论文」
    ↑
来源层（Source）          ← 原始数据节点：某封邮件、某条 Notion 笔记、某次对话

每次有新数据进来，系统会：把数据切成 ≤3,000 token 的小块（chunk）→ 归类到对应的来源层节点 → 更新上一层（主题层）的摘要 → 如果主题层有变化，更新全局层。

这就好比你在整理文件夹：收到新文件 → 归入对应文件夹 → 更新文件夹描述 → 如果文件夹多了，更新总目录索引。

当你问「昨天张总邮件里提到的方案是哪个？」，Memory Tree 直接导航到「张总 → 邮件 → 昨天」这条路径下的相关 chunk，而不是在整个向量空间里模糊搜索。这种结构性带来了更精准的回答，尤其是涉及人、时间、项目这类多维度问题时。

第二层：自动同步系统

OAuth（授权协议）连接 118+ 个第三方服务——Gmail、Notion、GitHub、Slack、Google Calendar 等。连接后，无需任何额外配置，系统每 20 分钟自动拉取新数据（auto-fetch），经过 Memory Tree 处理后入库存入本地。

这意味着：你授权 Gmail 后，新邮件自动出现在 AI 的可检索记忆里；你授权 GitHub 后，新 PR 和 Issue 自动被索引。数据全部本地存储在 ~/.openhuman 目录下，不主动发给 AI 对话的内容不会外传。

第三层：TokenJuice 压缩技术

大模型按 token 收费（1 token ≈ 0.5 个中文词）。工具输出、网页抓取、邮件原文往往体积庞大，直接喂给模型消耗巨大。TokenJuice 的压缩逻辑是：保留语义精华，去掉结构冗余。比如 ls -la 输出的几百行文件列表，压缩后只剩关键文件和大小；网页抓取结果去掉广告和导航栏只留正文。实际使用中最高能节省 80% 的 token 消耗。

自动模型路由

你不需要手动切换模型。OpenHuman 内置路由决策引擎，根据三个维度动态选择：

输入任务 → 是否涉及隐私（如个人邮件）？
    是 → 路由到本地模型（Ollama/LM Studio）
    否 → 判断任务复杂度
        简单（如「今天有什么待办」）→ 便宜快速模型（如 Gemini Flash）
        复杂（如「帮我分析这份竞品报告」）→ 高性能模型（如 Claude/GPT-4）

与 Obsidian 的双向同步

记忆不仅存在 SQLite 数据库，还会以 Markdown 格式同步到你的 Obsidian Vault 里。你可以在 Obsidian 里：查看 AI 记住了哪些信息、手动修正错误内容、在笔记间建立 [[wikilinks]] 形成知识网络、甚至把整份记忆导出到其他 Markdown 工具。这是对「黑盒记忆」的彻底颠覆——你的 AI 记住了什么，你一目了然，不满意还能自己改。

一句话总结

OpenHuman 是唯一能通过桌面 GUI + 自动同步 + 结构化记忆树实现「开箱即用型」个人 AI 助理的项目。它的门槛最低、记忆系统最强、对 token 成本控制最好。适合绝大多数用户，尤其是知识工作者。

决策指南

按痛点排序

  1. 「我想在微信/Telegram/Slack 里都能用同一个 AI，它还能自己操作浏览器」 → OpenClaw。Gateway 架构 + CDP 浏览器控制是目前唯一能同时做到这两点的方案。

  2. 「AI 每次帮我干完活就忘，同样的事情下次还得重教」 → Hermes Agent。它的闭环学习系统是目前唯一能自动从经验中创建技能并复用的实现。

  3. 「AI 从来不认识我，我想让它自己去读我的邮件、笔记、日历，然后自然地在后续对话中理解我」 → OpenHuman。Memory Tree + 118 服务自动同步 + Obsidian 同步，记忆能力在三个中最强且唯一用户可见可控。

  4. 「我不想碰命令行，装完就想用」 → OpenHuman。它是唯一有桌面安装包（DMG/EXE）的，双击即装。

可以组合

三者在设计上不冲突，甚至可以搭档：

  • OpenClaw（网关入口）+ Hermes（执行引擎）：你在微信发消息 → OpenClaw 接收 → 转给 Hermes 执行复杂多步任务 → 结果返回微信
  • OpenHuman（记忆底座）+ Hermes（行动引擎）：OpenHuman 通过自动同步构建你的长期记忆 → Hermes 基于记忆内容执行代码/浏览器操作
  • 注意：同时运行时必须各自使用独立的工作目录、独立的浏览器配置和独立的 OAuth 授权

三个你必须懂的技术概念

（如果读到这里你已经理解了，可跳过本节）

  • CDP（Chrome DevTools Protocol）：浏览器开放给外部程序的控制协议。外部工具通过 WebSocket 连接 Chrome，可以远程做打开页面、点击、截图等操作。它是所有浏览器自动化的底层依赖。
  • OAuth（开放授权协议）：你常见到的「用 Google 账号登录」就是 OAuth。应用可以在不拿到你密码的前提下获得受限权限（比如只读你的邮件），你随时可以收回授权。
  • Token（大模型计费单位）：1 token ≈ 0.5 个中文词。每次对话的输入 + 输出消耗一定数量的 token，乘以单价就是费用。TokenJuice 做的就是在不影响语义的前提下压缩内容，省 token = 省钱。
